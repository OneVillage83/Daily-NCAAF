# Daily NCAAF — Provider Coverage Probe Specification V2

**Phase:** B.2 — Empirical Coverage & PIT Probe  
**Status:** ACTIVE  
**Harness contract:** `DAILY_NCAAF_PHASE_B2_PROVIDER_COVERAGE_PROBE_V2`  
**Supersedes:** `PROVIDER_COVERAGE_PROBE_SPEC_V1.md` for new runs; V1 remains the original audit contract.

---

## 1. Why V2 exists

The first authenticated CFBD run exposed two questions the V1 aggregate contract could not resolve cleanly:

1. CFBD `wallclock` is completely absent in sampled 2004/2010/2014 PBP but highly populated in 2020/2024/2025, so the transition era must be measured rather than guessed;
2. CFBD `classification=fbs` season counts differ from the public cfbfastR schedule universe, so event-scope/classification composition must be recorded before cross-provider completeness comparisons.

V2 extends the measurement contract without changing the governing rule: this remains research-only evidence gathering, not production ingestion.

---

## 2. Secret and output rules remain unchanged

CFBD credentials are read only from:

```text
CFBD_API_KEY
```

The key must never be:

- committed;
- passed as a command-line argument;
- printed to terminal output;
- written into probe JSON;
- pasted into issues, PR comments or checked-in transcripts.

Local aggregate output belongs under ignored paths such as:

```text
local-data/probes/
```

## 3. V2 game summary contract

For `GET /games`, record:

```text
rows
unique_game_ids
duplicate_game_id_rows
completed_rows
incomplete_rows
neutral_site_rows
start_time_tbd_rows
score_missing_rows
home_conference_null_rows
away_conference_null_rows
home_classification_null_rows
away_classification_null_rows
classification_pair_counts
season_type_counts
incomplete_examples (capped)
```

Incomplete examples preserve only compact review fields needed to identify canceled/postponed/unresolved events.

The output must also state the exact provider query scope so row totals are not compared to another source without normalization.

---

## 4. V2 play summary contract

For `GET /plays`, record:

```text
rows
unique_game_ids
unique_play_ids
duplicate_play_id_rows
wallclock_null_rows
wallclock_null_rate
ppa_null_rows
ppa_null_rate
play_text_null_rows
play_text_null_rate
top_play_types
ppa_null_by_play_type
wallclock_null_by_play_type
```

The by-play-type views are required because some derived fields are structurally inapplicable to administrative/special-teams events.

---

## 5. Immediate timestamp-era probe

Run representative weeks for:

```text
2015
2016
2017
2018
2019
```

This is intended to locate the onset/transition of populated CFBD `wallclock` values between the fully-null 2014 sample and the nearly-complete 2020 sample.

Do not convert the first non-null season directly into a universal PIT guarantee. The result only establishes provider-field coverage by era.

---

## 6. Immediate event-universe probe

Include 2024 and 2026 in the same follow-up so game summaries reveal:

- FBS-vs-FBS counts;
- FBS-vs-FCS / FCS-vs-FBS counts returned by the filter;
- any other classification pairs;
- start-time TBD behavior;
- missing-score rows;
- the identity of incomplete historical rows.

Cross-provider season-count comparison remains invalid until both sources are normalized to the same event universe.

---

## 7. PIT interpretation rules locked by V1 authenticated evidence

The following are now empirical constraints:

```text
wallclock is optional by era
wallclock is not historical publication time
historical current API response != historical knowledge snapshot
acquired_at must be generated by our own capture layer
provider-derived PPA requires a separate feature/PIT contract
```

Prospective 2026 live capture is still required to measure publication/revision latency.

---

## 8. Completion condition for B.2-A

B.2-A may be considered complete enough to hand off to B.2-B when:

1. representative authenticated game/PBP access has succeeded;
2. major ID/null behavior is measured;
3. `wallclock` era boundaries are sufficiently located for conservative schema design;
4. classification/event-universe semantics are sufficiently explicit that provider row-count differences are not misclassified as coverage defects;
5. unresolved anomalies are documented as targeted B.2-C reconciliation cases.

B.2-A does not need to prove full historical completeness before B.2-B begins; it needs to prevent Phase C from encoding false assumptions.
