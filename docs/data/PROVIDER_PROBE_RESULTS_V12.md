## V2 side-orientation defect discovered

The V2 same-side team crosswalk reported four apparent conflicts:

```text

UTSA
Texas A&M
USC
```

They are generated by exactly two bowl events:

```text
401677085  UTSA vs Coastal Carolina
401677093  USC vs Texas A&M
```

CFBD and ESPN assigned opposite home/away sides to the same exact event IDs. The team pair and final score by team agree; only the provider side labels differ.

Therefore the V2 results:

```text
score mismatch = 2
team crosswalk conflict = 4
```

are instrumentation artifacts caused by raw home/away alignment.

Locked rule:

```text
same event + same participant set + swapped provider sides != identity conflict
home/away label != canonical participant identity
```

Canonical event participants must be aligned to program identity before scores or team crosswalks are compared.

For neutral/postseason events, provider `home` / `away` is retained as provenance-bearing observation metadata rather than an identity key.

## 2026 current-state snapshot

At the V2 acquisition:

```text
CFBD season rows                       888
SportsDataverse schedule rows            8
exact shared IDs                         8
raw ESPN-only IDs                        0
CFBD-only relative to that snapshot    880
```

All eight SportsDataverse events were exact CFBD event IDs and all eight kickoff timestamps agreed.

This is not evidence that SportsDataverse's historical 2026 coverage ceiling is eight games. It is a current publication snapshot that was a strict subset of CFBD's already-published season schedule.

Three of the eight matched events showed a live-state lag:

```text
401858201 Stanford vs Hawai'i
401864570 Florida State vs New Mexico State
401866408 Eastern Michigan vs Sacramento State
```

At our CFBD acquisition, CFBD marked them complete with final scores. The contemporaneously downloaded SportsDataverse asset still reported `STATUS_IN_PROGRESS` and intermediate scores.

Locked consequences:

```text
current provider snapshot != final season truth
provider publication/update cadence is source-specific
same game ID can carry different current lifecycle/score state across providers
```

Every current-season source observation therefore requires at minimum:

```text
provider
provider_record_id
acquired_at
source asset/version/hash
observed lifecycle state
observed score state
```

A later provider refresh creates a new observation; it must not overwrite what was known at an earlier acquisition.
